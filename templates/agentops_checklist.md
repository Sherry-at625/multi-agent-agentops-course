# AgentOps 课堂观测清单与评分标准

> 用途：在多智能体流水线运行过程中，由学生（或教师）对照记录每个 Agent 的执行轨迹、成本、质量与异常；运行结束后回放复盘，理解 AgentOps「观测—评估—回放—优化」闭环。

## 一、AgentOps 六大观测维度与课堂对应字段

| 观测维度 | 要回答的问题 | 记录位置（trace 模板字段） |
|---|---|---|
| 1. 追踪 Tracing | 这一步由哪个 Agent、在什么时间、调用了什么工具、产出了什么？ | agent_role、platform、task_step、tool_called、output_artifact、timestamp |
| 2. 输入输出记录 | 给 Agent 的任务与它返回的内容是什么？上下文是否完整传递？ | input_summary、output_summary |
| 3. 延迟与耗时 | 每一步花了多久？瓶颈在哪个环节？ | duration_sec |
| 4. Token 与成本 | 本轮消耗多少输入 / 输出 Token，估算成本多少？ | prompt_tokens、completion_tokens、total_tokens、estimated_cost_cny |
| 5. 质量评估 | 产物是否通过质检？问题出在哪里？ | status、qa_score、reviewer_notes、error_message |
| 6. 异常与回放 | 是否失败、重试几次、根因是什么、如何修复？ | retry_count、error_message、replay_findings（汇总表） |

## 二、单条轨迹记录要求（`agentops_trace_template.csv`）

1. 每个 Agent 的每一次关键执行记录一行；同一环节内多次重试按重试次数追加行。
2. `status` 取值：`success` / `retry` / `failed` / `skipped`。
3. `qa_score` 由质检 Agent 或人工按 1—5 打分：5 一次通过、3 经一次修改通过、1 严重退回。
4. 成本估算口径：课堂使用平台积分 / Token 近似折算即可，必须在表尾写明折算假设，不编造官方价格。
5. `input_summary`、`output_summary` 只写要点与文件路径，不粘贴长段对话。

## 三、单次运行复盘表（`agentops_run_summary.csv`）

每次完整流水线运行填写一行，汇总：

- 参与 Agent 数量、成功 / 失败步骤数、总耗时；
- 总 Token、估算成本、人工干预次数；
- 质检总分、主要失败环节、回放发现的根因；
- 本次优化动作（修改 Prompt、调整角色分工、补充规则、更换工具或模型）。

## 四、课堂评分标准（实践环节满分 100）

| 评分项 | 分值 | 观察要点 |
|---|---|---|
| 角色与任务拆解 | 15 | 五个角色职责清晰、依赖顺序正确、Prompt 边界明确 |
| 数据工程质量 | 20 | 清洗规则完整、报告条数可复核、无脏数据流入分析 |
| 分析与可视化 | 20 | 指标公式正确、分组齐全、图表规范、结论有数据支撑 |
| 质检闭环 | 15 | 独立复算、问题分级准确、退回与修复闭环可追溯 |
| 报告交付 | 15 | 结构完整、数字与质检数据一致、图表嵌入正确、格式规范 |
| AgentOps 记录与复盘 | 15 | 轨迹字段完整、耗时 / Token / 异常记录齐全、复盘结论具体可改进 |

## 五、常见故障与定位对照（回放时使用）

| 现象 | 可能定位环节 | 排查方向 |
|---|---|---|
| 分析结果仍出现负利润 / 重复订单 | 数据工程 Agent | 清洗规则是否执行、剔除条件是否覆盖 |
| 图表数值与 JSON 指标对不上 | 分析可视化 Agent | 是否重复分组、单位与口径是否一致 |
| 报告出现数据中不存在的结论 | 报告 Agent / 质检缺口 | 是否越过质检编造结论；质检清单是否覆盖结论核对 |
| Agent 反复修改同一处错误 | 编排者 / Prompt 设计 | 角色边界不清、交接摘要缺失、规则未共享 |
| 成本或耗时异常偏高 | 编排策略 | 上下文重复传递、无效重试、模型选择不当 |
| 上下文在交接后丢失 | 通信与记忆机制 | 交接物是否包含路径与结构化摘要、下游是否先核对产物 |

## 六、课堂复盘提问（课程收尾讨论）

1. 哪些任务适合拆分给多个 Agent，哪些任务单 Agent 更高效？判断依据是什么？
2. 质检 Agent 在流水线中带来了哪些成本，又避免了哪些下游返工？
3. 如果没有 AgentOps 轨迹记录，出现结果错误时能否快速定位责任环节？为什么？
4. 本次运行中哪一步最依赖人工判断？对应应该补充什么规则或工具？
