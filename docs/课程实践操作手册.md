# 《多智能体协作与 AgentOps》课程实践操作手册

> 适用课程：本科大数据专业 · 人工智能工具实践
> 案例主题：零售销售数据多智能体协作分析流水线
> 工具平台：Trae（AI-first 编码 IDE）、WorkBuddy（桌面 AI Agent 工作台）
> 课程时长：90 分钟（理论约 27 分钟，实践约 63 分钟）
> 版本日期：2026-11-01

---

## 一、课程目标

学完本课程，学生应当能够：

1. 说清单 Agent 与多智能体系统（Multi-Agent System, MAS）的区别，识别流水线、层级编排等常见协作架构；
2. 理解角色分工、任务分解、上下文交接、记忆与工具调用等多智能体协作关键机制；
3. 理解 AgentOps 的含义与六大观测维度，会在平台运行过程中记录追踪、耗时、Token、成本、质量与异常；
4. 在 Trae 与 WorkBuddy 中配置编排者、数据工程、分析可视化、质检、报告五个角色，完成一条可复现的数据分析流水线；
5. 依据质检意见进行回退修复，并基于轨迹记录完成复盘。

### 3.3 平台模式速查

**Trae**

- **IDE 模式**：保留编辑器、终端、调试、Git 工作流，适合精细控制代码改动；本案例的数据工程、分析环节使用。
- **SOLO 模式**：AI 主导，自然语言输入需求后自动规划、生成代码、测试与预览；支持任务拆解、多任务并行、自定义智能体与 MCP 工具。
- **权限模式**：命令默认可在沙箱运行；高风险命令需手动确认；课堂建议保持默认沙箱 + 手动确认。

**WorkBuddy**

- **Craft 模式（You say, I do）**：任务明确，Agent 直接执行交付，用于报告生成与排版。
- **Plan 模式（Think first, do second）**：先生成步骤方案，人工确认后执行，用于编排与复杂任务。
- **Ask 模式（Talk only, hands off）**：只做问答分析，不修改文件，适合质检评审。

## 四、实践案例背景

某区域连锁零售企业 2024-01-01 至 2025-12-31 的订单原始数据存于 `data/retail_sales_raw.csv`，共 3654 行（含刻意注入的缺失值、重复记录、日期格式不统一、负利润、异常数量）。业务方需要一份面向管理层的中文分析报告，回答：整体经营表现如何？哪些品类贡献最大、利润率如何？地区之间是否均衡？不同客户分层的价值差异？

**交付物要求**：清洗后数据集、清洗报告、指标文件、四张规范图表、质检报告、一份中文分析报告（Markdown + Word）。

**多智能体分工**：编排者统筹；数据工程 Agent 清洗；分析 Agent 计算与可视化；质检 Agent 独立把关；报告 Agent 汇总交付。

## 五、分步操作指引

### 步骤 0：建立项目与全局规则（教师带领，约 6 分钟）

1. 在 Trae 中打开课程文件夹作为项目目录。
2. 把 `prompts/00_global_rules.md` 内容粘贴为项目规则（`.trae/rules/global_rules.md`，或项目根目录 `AGENTS.md`），确保所有 Agent 共享数据字典与交接协议。
3. 核对 `data/retail_sales_raw.csv` 可正常读取；在终端运行一次 `python code/generate_dataset.py` 可复现原始数据（可选演示）。
4. 查看 `templates/agentops_trace_template.csv`，准备记录第一条轨迹。

**验收标准**：规则文件已加载；原始数据可读；学生理解五个角色与产物路径。

### 步骤 1：编排者拆解任务，数据工程 Agent 清洗（约 10 分钟）

1. 在 Trae 自定义智能体（SOLO Plan）或 WorkBuddy Plan 模式中创建 **Orchestrator**，粘贴 `01_orchestrator.md` 系统提示词；先出计划、人工确认后执行。
2. 发送课堂启动总指令（见 `01_orchestrator.md` 末尾），编排者先输出任务拆解清单与调度计划，人工确认后执行。
3. 创建 **Data Engineer** 智能体，粘贴 `02_data_engineer.md`；Orchestrator 向其分派数据清洗任务。
4. 由该 Agent 读取原始数据，先输出探查结果（规模、缺失、重复、异常），再生成并运行清洗脚本；教师可对照 `code/clean_analyze.py` 第 1 节检查规则覆盖度。
5. 交付 `data/retail_sales_cleaned.csv` 与 `outputs/cleaning_report.json`，按交接摘要格式回报各类问题处理条数。

**验收标准**

- 清洗报告包含：原始行数、日期缺失/不可解析条数、去重条数、异常数量剔除数、负利润剔除数、分层缺失回填数、清洗后行数与剔除比例；
- 清洗后数据无重复行、无负利润、无数量非正、无缺失日期；
- 销售额按 `quantity × unit_price × (1 − discount)` 口径复核。

**参考清洗结果（参考答案，供质检对照）**

| 处理项 | 条数 |
|---|---|
| 原始记录 | 3654 |
| 日期缺失剔除 | 72 |
| 整行去重 | 54 |
| 异常数量剔除 | 35 |
| 负利润剔除 | 105 |
| 客户分层缺失回填 | 163 |
| 清洗后有效订单 | 3388 |
| 剔除比例 | 7.28% |

### 步骤 2：分析可视化 Agent 计算指标与出图（约 12 分钟）

1. 创建 **Analyst** 智能体，粘贴 `03_analyst.md`；先让其核对清洗后数据质量，再开展分析。
2. 计算总体指标与品类、地区、客户分层、时间趋势分组指标，输出 `outputs/summary_metrics.json`。
3. 生成四张图表到 `outputs/charts/`：月度趋势、品类对比、地区占比、分层贡献。
4. 形成 3–5 条带数值的初步洞察，回报编排者。

**验收标准**：总体指标可由清洗后 CSV 复算；分组之和与总体一致；图表标题、单位、图例齐全，中文显示正常；结论不做无数据支撑的因果推断。

### 步骤 3：质检评审 Agent 独立核查与回退闭环（约 8 分钟）

1. 创建 **Reviewer** 智能体，粘贴 `04_reviewer.md`；在 WorkBuddy 中切换为 **Ask 只读模式**（只核查、不修改任何上游文件）。
2. 按 `agentops_checklist.md` 的 A/B/C 三组清单逐项核查，复算总体销售额、利润、订单数。
3. 输出 `outputs/qa_review.md`，给出「通过 / 有条件通过 / 退回」结论与问题清单。
4. 若退回，由编排者定位问题环节，退回对应 Agent 修复后重新质检；在轨迹表中记录重试次数与错误信息。

**验收标准**：质检结论与证据可追溯；退回意见指明环节、问题与修复要求；未通过质检的产物不进入报告环节。

### 步骤 4：WorkBuddy 汇总生成分析报告（约 12 分钟）

1. 在 WorkBuddy 新建任务，选择 **Plan 模式**；上传全局规则、指标 JSON、四张图表与质检报告。
2. 创建 **Reporter** 角色，粘贴 `05_reporter.md`；确认质检已通过后开始写作。
3. 按报告结构组织内容，嵌入图表，输出 `outputs/零售销售数据分析报告.md`，并导出 Word（.docx）版本；条件允许时附 Excel 指标摘要。
4. 报告中所有数字必须与 `summary_metrics.json` 一致；推测性内容标注为假设。

**验收标准**：结构完整（执行摘要、概况、趋势、品类、地区、分层、问题风险、建议、附录）；图表编号与正文对应；无越过质检的编造结论。

### 步骤 5：AgentOps 记录、回放与复盘（约 7 分钟）

1. 将本次运行每个 Agent 环节填入 `templates/agentops_trace_template.csv`：角色、步骤、工具、产物、状态、耗时、Token、估算成本、重试、错误、质检得分。
2. 填写 `templates/agentops_run_summary.csv`：总耗时、总 Token、人工干预次数、质检总分、主要失败点与回放发现。
3. 回放平台对话流与任务面板，定位一次失败或退回环节，讨论根因与改进（Prompt、规则、分工、模型、工具）。

## 六、常见问题与排查

| 现象 | 可能原因 | 处理方式 |
|---|---|---|
| 终端提示缺少 pandas / matplotlib | Python 环境未装依赖 | 在 Trae 终端执行 `pip install pandas matplotlib numpy`，或使用沙箱自动配置 |
| 图表中文显示为方框 | 未配置中文字体 | 在脚本中设置 `plt.rcParams["font.sans-serif"]` 为系统可用中文字体（如 Noto Sans CJK SC、Microsoft YaHei） |
| Agent 读不到新生成的文件 | 上下文未刷新或路径错误 | 在对话中 `@` 引用正确文件路径；核对工作目录；重新发送包含路径的任务指令 |
| 清洗后仍出现负利润 | 剔除条件未生效或未重新运行脚本 | 检查 `profit < 0` 过滤条件；重新执行清洗脚本并覆盖输出 |
| 图表数值与 JSON 指标不一致 | 重复分组或口径混用 | 让质检 Agent 复算；退回分析 Agent 统一口径后重新出图 |
| 报告出现数据中不存在的结论 | 报告 Agent 越过质检自由发挥 | 回退到 Reporter，要求仅引用质检通过的指标；在全局规则中强化结论约束 |
| 同一问题反复返工 | 角色边界不清、交接摘要缺失 | 检查交接协议是否执行；在全局规则中补充必填交接字段；必要时拆分角色职责 |
| 平台积分 / 额度不足 | 免费额度消耗较快 | 教师提前充值或规划分组使用；记录 Token 消耗作为成本教学素材 |

## 七、参考结果速览（基于参考答案运行）

> 以下数字来自参考答案脚本在 `retail_sales_raw.csv` 上的实际运行，供教师核对学生产物，不要求学生逐字复现。

- 有效订单 3388 笔；总销售额 3,888,210.60 元；总利润 1,719,269.64 元；整体利润率 44.22%；客单价 1,147.64 元。
- 品类：电子产品销售额占比 40.9%（利润率 36.6%）规模第一；美妆个护利润率 55.0% 为最高；食品饮料规模最小（3.8%）。
- 地区：华南、华中、华东销售额位列前三，各区利润率集中在 43.6%–45.0%，差异不大。
- 客户分层：老客贡献销售额 36.8%；新客 29.1%；会员 28.5%；未知分层订单 163 笔，建议后续补全客户标签。
- 年度对比：2024 年销售额约 195.7 万元，2025 年约 193.1 万元，基本持平；月度峰值出现在 2024 年 10 月。

## 八、安全与合规提示

1. 课堂数据为合成教学数据，不含真实个人信息；不得将真实客户隐私数据直接接入未审核的第三方 Agent。
2. 不执行与任务无关的文件删除、批量写入或系统命令；高风险命令先经人工确认。
3. 对外发布报告前，由教师核对数据口径与结论；Agent 生成内容须经人工复核后才可作为业务决策依据。
4. 记录与复盘材料仅用于课堂教学，不包含账号密钥、API Key 等敏感信息。
