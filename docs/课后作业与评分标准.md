# 课后作业与评分标准

> 课程：多智能体协作与 AgentOps · 本科大数据专业人工智能工具实践
> 配套：《课程实践操作手册.md》、Prompt 包、AgentOps 模板

## 一、课堂随堂练习（课内完成，计入平时成绩 40%）

### 任务内容

以 3—4 人为一组，在 Trae 与 WorkBuddy 中复现零售销售数据分析多智能体流水线，完成五步实践流程，并提交以下产物：

1. `data/retail_sales_cleaned.csv` 与 `outputs/cleaning_report.json`；
2. `outputs/summary_metrics.json` 与 `outputs/charts/` 四张图表；
3. `outputs/qa_review.md` 质检报告（含至少一次问题记录与处理闭环，若无问题需写明核查项与通过依据）；
4. `outputs/零售销售数据分析报告.md` 与导出的 Word 版本；
5. `templates/agentops_trace_template.csv` 已填写的轨迹记录、`templates/agentops_run_summary.csv` 运行汇总；
6. 每组 3 分钟口头复盘：架构选择、最容易出错的环节、AgentOps 记录到的主要问题与改进措施。

### 课内要求

- 必须体现多智能体分工，不得由单个 Agent 一口气完成全部环节；
- 必须包含独立质检环节与至少一次显式的交接；
- 所有指标数字可由清洗后数据复算；
- 轨迹记录与实际平台对话、产物时间顺序一致。

## 二、课后拓展作业（课后一周内提交，计入平时成绩 60%）

### 作业 A：架构改造与对比（必做）

在课堂零售案例基础上，完成两项改造并形成对比报告（不少于 1500 字）：

1. **架构对比**：把当前「流水线顺序协作」改造为「Orchestrator-Worker 层级编排」：由编排者并行分派数据探查、指标计算、图表生成等子任务，再由编排者汇总。记录两种架构下的环节耗时、Token 消耗、人工干预次数与出错点差异。
2. **角色改造**：新增一名「错误诊断 Agent」，在质检退回时自动分析错误日志、定位问题环节并给出修复建议；在轨迹表中记录它介入的次数与效果。
3. 提交内容：改造后的角色 Prompt、新的轨迹与汇总记录、对比数据表、结论分析（什么任务适合流水线、什么任务适合并行编排）。

### 作业 B：自选场景多智能体设计与实现（二选一）

**场景 B1：商品评论/舆情分析流水线**

- 输入：提供的评论数据集（教师另发或公开数据集）；
- 角色建议：采集/读取 Agent、清洗分词 Agent、情感与主题分析 Agent、质检 Agent、舆情报告 Agent；
- 要求：完成情感分布、主题聚类（关键词）、负面评论归类，输出可视化图表与图文报告；记录 AgentOps 轨迹。

**场景 B2：数据采集—清洗—建模—报告流水线**

- 输入：公开统计数据或课程给定 CSV；
- 角色建议：数据获取 Agent、清洗特征工程 Agent、建模训练 Agent、结果评估 Agent、报告 Agent；
- 要求：选择一个可解释的预测或分类任务，记录特征、模型、指标（准确率 / 精确率 / 召回率等），由质检 Agent 核查数据泄露与指标口径，输出建模报告。

### 作业 B 通用要求

1. 先用文字给出系统设计图：角色、职责、输入输出、协作架构、交接物、异常回退路径；
2. 在 Trae 或 WorkBuddy 中实际跑通流水线，保留平台对话与产物记录；
3. 完成 AgentOps 轨迹表与运行汇总，至少分析一个失败案例的根因；
4. 报告中区分「模型/数据事实」与「分析判断、改进假设」；
5. 严禁直接复制教师参考答案，小组分工需在报告首页列明。

## 三、评分标准（百分制）

### 3.1 课内练习评分（40 分）

| 评分项 | 分值 | 评分要点 |
|---|---|---|
| 角色与任务拆解 | 6 | 五角色职责清晰、依赖顺序正确、Prompt 边界明确 |
| 数据工程质量 | 8 | 清洗规则完整、报告条数可复核、脏数据未流入分析 |
| 分析与可视化 | 8 | 指标公式正确、分组齐全、图表规范、结论有数值支撑 |
| 质检闭环 | 6 | 独立复算、问题分级准确、退回—修复—复检过程可追溯 |
| 报告交付 | 6 | 结构完整、数字与质检一致、图表嵌入正确、格式规范 |
| AgentOps 记录与复盘 | 6 | 轨迹字段完整、耗时/Token/异常记录齐全、复盘具体 |

### 3.2 课后作业评分（60 分）

| 评分项 | 分值 | 评分要点 |
|---|---|---|
| 系统设计完整性 | 12 | 角色、数据流、架构、回退机制设计清晰合理，图文化表达 |
| 实现与运行结果 | 16 | 流水线可复现、产物齐全、指标结果合理且可复核 |
| AgentOps 应用深度 | 12 | 轨迹与成本/耗时记录完整，失败根因分析到位，提出可执行改进 |
| 对比分析与论证 | 10 | 架构对比有数据支撑，结论回答适用边界问题，逻辑自洽 |
| 报告写作规范 | 6 | 结构清晰、术语准确、引用可追溯、无编造数据 |
| 分工与原创性 | 4 | 分工明确，独立完成度高，无抄袭 |

### 3.3 等级换算（供教师参考）

- 优秀（90–100）：流水线一次跑通或闭环完整，AgentOps 记录可支撑复盘，架构分析有独立见解；
- 良好（80–89）：主要产物齐全，存在少量口径或格式问题但已修正；
- 中等（70–79）：基本跑通流程，质检与复盘记录较薄弱；
- 及格（60–69）：产物不全或部分环节由单 Agent 代劳，AgentOps 记录缺失；
- 不及格（60 以下）：未完成流水线、数据不可复算、存在明显抄袭或编造。

## 四、提交规范

1. 以小组为单位提交压缩包，命名 `课程名_组号_组长姓名.zip`；
2. 目录沿用本课程资料包结构，代码、数据、Prompt、产物、模板、报告分目录存放；
3. 报告同时提交 Markdown 与 Word（或 PDF）；图表为 PNG，指标为 JSON 或 CSV；
4. 提交前对照本标准逐项自查，附一份《提交自检清单》；
5. 涉及公开数据时注明来源与获取日期；使用合成数据需说明生成方式。
