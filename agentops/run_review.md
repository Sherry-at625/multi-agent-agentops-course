## 二、主要失败点拆解（T004）

**现象**：四张图表全部落盘，但所有中文字形渲染为方框（豆腐块），图表完全不可读。

**错误信息**：`Glyph 26376 (\N{CJK UNIFIED IDEOGRAPH-6708}) missing from font(s) DejaVu Sans`

**根因（三层）**

| 层次 | 根因 | 证据 |
|---|---|---|
| 直接原因 | 脚本照搬参考资料的 `font.sans-serif = ["Noto Sans CJK SC"]`，该字体是 Linux 环境自带，Windows 上不存在 | `findfont: Generic family 'sans-serif' not found` 告警刷屏 30+ 行 |
| 放大原因 | matplotlib 对缺字形只发 `UserWarning`，**不中断执行**，脚本把「渲染失败」当成成功继续跑完 | 四张 PNG 均正常生成（78 KB / 61 KB / 79 KB / 74 KB），文件大小无异常 |
| 深层原因 | 交付验收标准里写了「中文显示正常」，但脚本中**没有任何自动校验**去验证这条标准 | 靠人工看图才发现，若无人看图则会带着缺陷进入质检 |

**修复动作（T005）**

1. 字体改为候选链：`Microsoft YaHei → SimHei → PingFang SC → Noto Sans CJK SC → Source Han Sans SC → WenQuanYi Zen Hei`，逐个探测系统真实可用字体。
2. 增加**字形级断言**：用 `FT2Font.get_char_index(ord("月"))` 检查字体文件是否真的包含汉字字形，名字存在但字形缺失也会被拦下。
3. 找不到可用字体时 `raise SystemExit`，**宁可中断也不静默降级**。
4. 顺带修复同批发现的三处规范问题：图 4 纵轴 `1e6` 科学计数改万元刻度、图 3 浅色扇区白字改按亮度自适应、图 1 轴范围越界到 2026-01。

**改进归属**：属于「**工具/代码层**」改进而非 Prompt 层——因为这条标准是可判定的（字体是否含汉字字形），能被断言就不该靠人眼。

## 三、第二处回退（T008）：可追溯性缺口

**触发**：质检 D12 指出「13 条销售额被覆盖，但报告未说明该字段统计范围是清洗后剩余记录还是原始全量」。

**性质**：不是数值错误（数值本身经复算正确），而是**口径可解释性缺陷**——读者拿到 `销售额重算修正条数: 13` 时，无法判断为什么原始数据里明显有 49 条不符。

**处置**：编排者判定为非退回级问题，但因「可追溯性」是 AgentOps 的核心资产，仍主动退回 Data Engineer 补一次留痕：新增 `销售额重算统计范围` 口径说明、`销售额重算原始不符条数: 49`、`销售额重算修正订单号`（13 个 order_id）。

**启示**：这类问题的成本极低（98 秒、8,300 token），但收益是「任何一个数字都能被追问到源头」。**回退的成本应该与「未来被追问的概率」比较，而不是与「当前是否影响结论」比较。**

## 五、六节复盘四问（对应 `templates/agentops_checklist.md`）

### 问 1：哪些任务适合拆分，哪些单 Agent 更高效？

**适合拆分**：清洗与分析。两者的**验收标准维度不同**——清洗看「脏数据是否清零」，分析看「口径是否自洽、结论是否有据」。拆开后每个环节有独立的可断言标准，失败能被精确定位到「数据错」还是「算法错」。本次 T004 的图表缺陷如果没有独立的分析环节边界，就会和清洗问题混在一起排查。

**单 Agent 更高效**：报告撰写。T009 的输入是已经收敛的 JSON + 4 图 + 质检意见，本质是「把结构化事实翻译成叙述」，没有需要协商的中间状态，拆给多个 Agent 只会增加交接损耗。

**判断依据**：看**中间产物是否需要被独立验收**。需要 → 拆；不需要 → 合。

### 问 2：质检 Agent 的成本与收益

**成本**：32,700 token（18.6%）、434 秒（18.9%）、1 次出报告的人工阅读。
**收益**：
- 拦住 1 处口径歧义（D12 → 触发 T008 回退，避免报告被追问时无法解释）；
- 提前定性 2 条「不得写进报告」的表述边界（D13 未知分层、D15 峰谷归因），避免 Reporter 越界；
- 用独立代码复算 12 项，把「数字对不对」从「信任上游」变成「可验证」。

**结论**：质检的价值不在「发现问题数」，而在「**把不可验证的信任变成可验证的证据**」。本次 12 项全过，看似「白花 token」，但正是这 12 项全过才让报告里的每个数字可以被一句话追问到底。

### 问 3：没有轨迹记录，能否快速定位责任环节？

不能。以 T004 为例：现象是「图表中文是方框」，这个现象可以追溯到**至少三个**环节——Analyst 的字体配置（实际根因）、运行环境的字体缺失（环境问题）、甚至字体文件本身损坏（系统问题）。没有轨迹里的 `tool_called=matplotlib.savefig`、`input_summary=字体配置仅写 Noto Sans CJK SC`、`error_message=Glyph missing`，排查只能从「重跑一遍看还错不错」开始。

有了轨迹，定位路径是：**现象 → trace 中 status=failed 的那一行 → error_message → 该行的 input_summary → 根因**，三步到根因，耗时不到 1 分钟。

**这正是 AgentOps 的核心价值：把「调试」从考古变成查表。**

### 问 4：哪一步最依赖人工判断？应补什么规则或工具？

**最依赖人工判断的是「图表是否可读」**——本次恰恰在这里翻车。因为「可读」过去被当成审美判断，没有可断言的标准。

**应补的规则/工具**：
1. **已补（本次）**：字体字形断言（`FT2Font.get_char_index`），把「中文能否显示」变成布尔值。
2. **建议补（下次）**：图表交付前增加「像素级非空断言」——检查图上是否存在连续 3 个以上相同的方块像素块（豆腐块特征），用机器替代人眼做第一道筛。
3. **建议补（下次）**：在全局规则里把「图表验收标准」从定性描述改为**可执行检查清单**（DPI 数值、字体名、轴标签非空、图例存在），让 Analyst 自检与 Reviewer 复核使用同一份清单。

## 六、本次运行的三个结论

1. **失败不可怕，静默失败才可怕**。T004 的真正问题不是字体配错（这是环境差异，必然发生），而是 matplotlib 只警告不报错、脚本没有任何断言，导致缺陷一路流到人工眼前。**凡是验收标准里写了的，就必须有代码断言。**
2. **回退的价值应按「未来被追问的概率」衡量，而不是「当下是否影响结论」**。T008 花 98 秒补留痕，换来的是「任何一个数字都能追到源头」。
3. **质检的成本是显性的、收益是隐性的**。本次质检 12 项全过、看似零收益，但它把报告从「相信 Agent」变成了「可以复算」。在 Agent 生成内容占比越来越高的场景里，**可复算性本身就是交付物的一部分**。
